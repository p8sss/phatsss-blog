# A RAG request from question to cited answer

**The question:** Where do chunking, retrieval, reranking and generation each happen?

**The short answer:** Chunking and embedding happen once, offline, when documents are ingested. At question time the app retrieves a broad set of candidate chunks, a reranker narrows them to the best few, and the LLM writes an answer that cites them by number. The app then checks that every citation points at a chunk it actually sent.

## Each stage, and how it fails

| Stage | When | Tuned for | Typical failure |
| --- | --- | --- | --- |
| Chunking | At ingest | Chunks that each hold one idea | Splits a table or a step list in half |
| Embedding | At ingest, and once per question | Same model on both sides | Mixed models after an upgrade |
| Retrieval | Per question | Recall: fetch more than you need | The right chunk never makes the short list |
| Reranking | Per question | Precision: keep only what answers the question | Too few kept, so a needed fact is dropped |
| Generation | Per question | Faithfulness to the sources | Answers from training data instead of the sources |

When an answer is wrong, find the first stage that lost the fact. Was the fact in the retrieved set? In the reranked set? In the prompt? Most fixes belong upstream of the model.

## Building the prompt and checking citations

```ts title="answer-with-citations.ts"
export interface Chunk {
  readonly id: string;
  readonly source: string; // e.g. "refunds.md §2"
  readonly text: string;
}

export function buildPrompt(question: string, chunks: readonly Chunk[]): string {
  const sources = chunks
    .map((c, i) => `<source id="${i + 1}" ref="${c.source}">\n${c.text}\n</source>`)
    .join("\n");
  return [
    sources,
    "Answer the question using only the sources above.",
    "Cite every claim with its source number, like [1].",
    "If the sources do not answer the question, say that you do not know.",
    `Question: ${question}`,
  ].join("\n\n");
}

/** Maps [n] markers back to the chunks that were sent, and reports any that point nowhere. */
export function checkCitations(
  answer: string,
  chunks: readonly Chunk[],
): { cited: Chunk[]; unknown: number[] } {
  const numbers = [...new Set([...answer.matchAll(/\[(\d+)\]/g)].map((m) => Number(m[1])))];
  const isKnown = (n: number) => n >= 1 && n <= chunks.length;
  return {
    cited: numbers.filter(isKnown).map((n) => chunks[n - 1]),
    unknown: numbers.filter((n) => !isKnown(n)),
  };
}
```

Some APIs can do this for you. Anthropic's citations feature, for example, returns the exact passages each part of the answer came from.

## Pitfalls

- **Chunks without context.** "It increased by 3%" means nothing alone. Prepend the document title and section heading to each chunk before embedding.
- **Vector search alone misses exact terms.** Product codes, error messages and names often need keyword search. Merge both result lists.
- **Stuffing the prompt.** Twenty loosely related chunks dilute the good ones and cost tokens. Rerank and keep a few.
- **Stale indexes.** A document edited yesterday but not re-ingested gives confidently outdated answers. Re-ingest on change and store a version or date with each chunk.
- **Retrieved text is untrusted input.** A document can contain instructions aimed at the model. Treat it as data, and never let it trigger actions on its own.
