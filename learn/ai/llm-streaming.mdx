# Streaming a response

**The question:** How do tokens reach the browser before the answer is finished?

**The short answer:** The model API sends each piece of text as a server-sent event the moment it is generated. Your server forwards each piece down its own open response, and the browser reads the body as a stream. The answer takes as long as before, but the first words appear much sooner.

## The events, in order

| Event | When | What to do with it |
| --- | --- | --- |
| `message_start` | Once, first | Note the message id |
| `content_block_start` | A text, thinking or tool-use block begins | Prepare to collect it |
| `content_block_delta` | Many times | Append `text_delta` text; collect `input_json_delta` pieces of tool input; `thinking_delta` and `signature_delta` belong to a thinking block |
| `content_block_stop` | A block ends | A tool call's input is now complete JSON |
| `message_delta` | Near the end | Read the stop reason and output token count |
| `message_stop` | Once, last | Done |
| `ping` | Any time | Ignore; it keeps the connection alive |
| `error` | Any time | Show an error; the HTTP status was already 200 |

These are the Anthropic Messages API names. Other providers use different event names for the same steps.

## Server and browser

```ts title="app/api/chat/route.ts"
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

export async function POST(req: Request): Promise<Response> {
  const { question } = await req.json();
  if (typeof question !== "string" || question.length === 0) {
    return new Response("question is required", { status: 400 });
  }

  const stream = client.messages.stream({
    model: "claude-opus-5-5",
    max_tokens: 4096,
    messages: [{ role: "user", content: question }],
  });
  const encoder = new TextEncoder();

  const body = new ReadableStream<Uint8Array>({
    async start(controller) {
      try {
        for await (const event of stream) {
          if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
            controller.enqueue(encoder.encode(event.delta.text));
          }
        }
        controller.close();
      } catch (err) {
        controller.error(err);
      }
    },
    cancel() {
      stream.abort(); // the browser went away: stop generating, stop paying
    },
  });

  return new Response(body, {
    headers: { "Content-Type": "text/plain; charset=utf-8", "Cache-Control": "no-store" },
  });
}
```

```ts title="chat.ts"
export async function ask(question: string, output: HTMLElement, signal: AbortSignal) {
  const res = await fetch("/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ question }),
    signal, // a Stop button calls abort() on its controller
  });
  if (!res.ok || !res.body) throw new Error(`chat failed: ${res.status}`);

  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  for (;;) {
    const { value, done } = await reader.read();
    if (done) break;
    output.textContent += value;
  }
}
```

Your own hop can be plain text chunks, as here. Use server-sent events on that hop too if the browser needs more than text, such as tool progress or usage.

## Pitfalls

- **A buffering proxy.** Nginx, a CDN or response compression can hold chunks back and deliver the whole answer at once. Turn buffering off for this route.
- **Errors after 200.** A stream can fail halfway, for example when the API is overloaded. Handle the error event and show what arrived so far.
- **Generating for nobody.** If the user closes the tab, abort the upstream request. Otherwise you pay for tokens no one reads.
- **Parsing tool input too early.** Tool arguments stream as partial JSON. Parse them only when the block ends.
- **Re-rendering on every token.** Updating a large React tree for each token can stutter. Batch updates per animation frame.
