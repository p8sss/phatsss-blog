# The agent loop

**The question:** How does a model reason, call a tool, read the result and decide to stop?

**The short answer:** Your code calls the model in a loop. Each time the model asks for a tool, your code runs it and sends the result back with the whole conversation. The loop ends when the model answers with plain text, or when your code hits a limit.

## The loop in code

This uses the Anthropic TypeScript SDK. Other providers have the same shape with different field names.

```ts title="agent.ts"
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();
const MAX_TURNS = 10;

// Your tool definitions, and a function that runs one call and returns text
declare const tools: Anthropic.Tool[];
declare function runTool(name: string, input: unknown): Promise<string>;

export async function runAgent(question: string): Promise<Anthropic.Message> {
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: question }];

  for (let turn = 1; turn <= MAX_TURNS; turn++) {
    const response = await client.messages.create({
      model: "claude-opus-5-5",
      max_tokens: 16000,
      tools,
      messages,
    });
    // end_turn, max_tokens, refusal and the rest: the model is not asking for a tool
    if (response.stop_reason !== "tool_use") return response;

    messages.push({ role: "assistant", content: response.content });
    const calls = response.content.filter(
      (block): block is Anthropic.ToolUseBlock => block.type === "tool_use",
    );
    // every result goes back in ONE user message, matched by tool_use_id
    const results = await Promise.all(
      calls.map(async (call): Promise<Anthropic.ToolResultBlockParam> => {
        try {
          return { type: "tool_result", tool_use_id: call.id, content: await runTool(call.name, call.input) };
        } catch (err) {
          return { type: "tool_result", tool_use_id: call.id, content: String(err), is_error: true };
        }
      }),
    );
    messages.push({ role: "user", content: results });
  }
  throw new Error(`agent stopped after ${MAX_TURNS} turns`);
}
```

The SDKs also ship a tool runner helper that writes this loop for you. It helps to see the plain version once.

## Who decides what

| Decision | Made by | Why |
| --- | --- | --- |
| Which tool to call, with which arguments | The model | That is the judgement you are paying for |
| Whether the tool actually runs | Your code | Permissions, validation and approval live here |
| When the task is done | The model, through its stop reason | It can tell when it has enough to answer |
| When to give up | Your code | Turn limits and budgets must not depend on the model |

## Pitfalls

- **No turn limit.** A model that keeps getting unhelpful results can call tools forever. Cap turns, tokens or money in code.
- **Dropping failed calls.** If a tool throws, return the error as a result. Leaving a call unanswered breaks the conversation, and the model cannot recover from an error it never saw.
- **Splitting parallel results.** When the model asks for several tools at once, send all results back in one message.
- **Context that only grows.** Every tool result stays in the history. Long tool outputs make each later turn slower and more expensive. Return only what the model needs.
- **An agent where a workflow would do.** If the steps are always the same, write them as plain code that calls the model. Agents earn their cost on open-ended tasks.
