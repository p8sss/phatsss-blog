# Sessions vs JWT vs opaque tokens

**The question:** where does state live, and how do you revoke each?

**The short answer:** a session keeps state on the server and revokes by deleting it. A JWT carries its state inside a signed token, so it is hard to revoke before it expires. An opaque token keeps state with its issuer and revokes there.

## The trade-off in one line

The more state the token carries, the less the server must look up, and the harder it is to take back. Sessions and opaque tokens trade a lookup for instant revocation. JWTs trade revocation for no lookup.

## Common hybrids

- **Short JWT, long refresh token.** The access token lives for minutes. The refresh token is stored server-side and can be revoked.
- **Session at the edge, JWT inside.** A gateway checks the browser's session cookie, then passes a short internal JWT to backend services.
- **Opaque outside, JWT inside.** Third parties get opaque tokens. A gateway introspects them and forwards a JWT.
