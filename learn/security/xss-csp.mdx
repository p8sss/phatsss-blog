# XSS, and how CSP contains it

**The question:** how does a script get into the page, and what does the browser block?

**The short answer:** cross-site scripting happens when user-supplied text is written into a page as HTML, so the browser runs it as your site's code. Encoding output turns it back into text. A Content Security Policy is the safety net that blocks scripts you didn't send.

## Three ways the script gets in

| Type | Where the payload lives | Example |
| --- | --- | --- |
| Stored | In your database | A comment or profile field shown to other users, as in the flow |
| Reflected | In the request | A search term echoed back into the results page |
| DOM-based | Only in the browser | Client code writes `location.hash` into `innerHTML` |

All three end the same way: text that should have been data is parsed as markup.

## A nonce-based CSP in Express

```ts title="csp.ts"
import crypto from 'node:crypto';
import type {NextFunction, Request, Response} from 'express';

export function csp(req: Request, res: Response, next: NextFunction) {
  const nonce = crypto.randomBytes(16).toString('base64');
  res.locals.cspNonce = nonce;
  res.setHeader(
    'Content-Security-Policy',
    `script-src 'nonce-${nonce}' 'strict-dynamic'; object-src 'none'; base-uri 'none'`,
  );
  next();
}
// in your templates: <script nonce="<%= cspNonce %>" src="/app.js"></script>
```

- **A fresh nonce on every response.** An attacker who sees a fixed nonce once can copy it into every injected script.
- **`'strict-dynamic'`** passes trust from a nonced script to the scripts it adds, so you don't maintain a list of hosts. Browsers that support it ignore host lists in `script-src`.
- **Roll out with `Content-Security-Policy-Report-Only`** first, and watch the reports before you enforce.

## Pitfalls

- **Encoding for the wrong context.** HTML-escaping a value doesn't make it safe inside a `<script>` block, an attribute without quotes, or a `javascript:` URL. Encode for where the value lands.
- **`'unsafe-inline'` without a nonce** lets every inline script run, which switches off most of what CSP protects. Browsers ignore it once a nonce or hash is present.
- **HttpOnly isn't a fix.** It keeps the cookie out of reach, but an injected script can still act as the user through the page.
