# Password login with bcrypt

**The question:** what happens to a password at sign-up and at login?

**The short answer:** at sign-up the server salts and hashes the password with a deliberately slow function, and stores only the result. At login it hashes the attempt the same way and compares. The password itself is never stored.

## Reading a bcrypt hash

A bcrypt hash is one 60-character string that carries everything needed to check a password later.

| Part | Example | Meaning |
| --- | --- | --- |
| Algorithm | `$2b$` | The bcrypt version |
| Cost | `12$` | The work factor: 2^12 rounds of key setup |
| Salt | 22 characters | 16 random bytes, unique per password |
| Hash | 31 characters | The result |

Because the salt is unique, two users with the same password get different hashes. Precomputed tables are useless.

## Pitfalls

- **The 72-byte limit.** bcrypt only uses the first 72 bytes of input. Bytes, not characters, so emoji and accented text hit it sooner. Cap password length at 72 bytes, or choose Argon2id.
- **Do not pre-hash with plain SHA.** Raw hash output can contain null bytes that some bcrypt implementations stop at. If you must pre-hash, use an HMAC with a secret pepper and Base64-encode the output.
- **Pick a cost that is slow but bearable.** OWASP asks for a work factor of at least 10. Measure on your own hardware and raise it as machines get faster.
- **Rehash on login.** When you raise the cost, check `bcrypt.getRounds(hash)` after a successful login and store a new hash.
- **Do not leak which part was wrong.** Return the same error for an unknown email and a wrong password. Run a dummy compare for unknown emails too, so the response time does not give it away. Rate limit attempts.

## Is bcrypt still the right choice?

OWASP now recommends Argon2id first, then scrypt. It lists bcrypt for legacy systems, with a work factor of at least 10. bcrypt is still far better than any fast hash such as SHA-256. For a new system, Argon2id is the stronger default.

## In code

```ts title="passwords.ts"
import bcrypt from 'bcrypt';

const COST = 12;

export async function hashPassword(password: string): Promise<string> {
  if (Buffer.byteLength(password, 'utf8') > 72) {
    throw new Error('Password is too long');
  }
  return bcrypt.hash(password, COST);
}

export async function checkPassword(password: string, stored: string): Promise<boolean> {
  return bcrypt.compare(password, stored);
}

export function needsRehash(stored: string): boolean {
  return bcrypt.getRounds(stored) < COST;
}
```
