# An authorization check with a policy engine

**The question:** what happens between "can this user edit this doc?" and yes or no?

**The short answer:** the API gathers facts about the user, the action and the document, and sends them to a policy engine. The engine evaluates its rules and answers allow or deny. The API enforces that answer.

## Who does what

| Role | Short name | In this flow |
| --- | --- | --- |
| Policy enforcement point | PEP | The API server |
| Policy decision point | PDP | OPA |
| Policy information point | PIP | The database the API reads attributes from |

## The policy

```rego title="docs_authz.rego"
package docs.authz

default allow := false

allow if {
    input.action == "edit"
    input.resource.owner == input.user.id
}

allow if {
    input.action == "edit"
    "editor" in input.user.roles
    input.resource.org == input.user.org
}
```

## Pitfalls

- **Treat no answer as deny.** A timeout, an error or a missing result must all fail closed.
- **Check every path.** A policy only protects the endpoints that ask it.
- **Filter lists in the query.** For "show me my docs", do not fetch every row and check each one. Push the rule into the query.
